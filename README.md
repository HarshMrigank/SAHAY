# Sahay

Sahay is an AI-powered mental health monitoring system with verified victim and government counsellor onboarding.

## Run the client

From the `Prototype` directory, use:

```powershell
npm install
npm run dev
```

The local environment files are already present at `client/.env` and `server/.env`. OAuth is not used. The administrator is an internal approval account:

```text
Email: admin@sahay.com
Password: SahayAdmin@2026!
```

Start the API before using this account. Change this password before deployment.

For the survivor dashboard demo, use:

```text
Email: victim@sahay.com
Password: SahayVictim@2026!
```

The landing page provides separate registration flows for victims and government counsellors. Both upload a verification document and remain pending until the administrator approves them. To access the government panel, click **Government portal** in the top navigation or **Administrator console** in the footer.

Admin sign-in:

```text
Email: admin@sahay.com
Password: SahayAdmin@2026!
```

After signing in, the government panel shows the verification queue, uploaded documents, approval/rejection actions, and approved users grouped by state and district.

## Database migration

Run [`server/app/migration.sql`](server/app/migration.sql) in the Supabase SQL Editor, or start the API once; startup creates the same `sahay_users` table automatically. The API stores registration metadata and uploaded verification documents in PostgreSQL/Supabase.

## Run the API

```powershell
cd server
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload
```

The API exposes `GET /health`, `POST /auth/login`, `POST /auth/register`, `GET /admin/pending`, `PATCH /admin/users/{id}/{approved|rejected}`, and the JWT-protected `GET /auth/me`.

## Phase 2 AI monitoring

Authorized survivor accounts can use the **AI monitoring** tab to submit a consent-based wellbeing check-in. The backend applies a transparent, deterministic distress/CARVE screening rubric and safety rules. If `GROK_API_KEY` is configured in `server/.env`, Grok supplies a strictly validated explanatory summary; it never controls the final scores and is never exposed to the browser.

The result is an AI-assisted screening, not a diagnosis. High or urgent results are marked for human review. Run [`server/app/migration.sql`](server/app/migration.sql) in Supabase SQL Editor to create the assessment and review tables if startup migrations are not enabled.

## Phase 3 alerts and intervention workflow

Each assessment is evaluated by `server/app/alert_engine.py`, a deterministic, configurable rules engine. It can create deduplicated CRITICAL/HIGH alerts for urgent safety, high distress, rapid score change, high CARVE, or combined indicators. Grok never creates or closes alerts. Authorized counsellors/supervisors review alerts through the **Alerts & intervention center**, then use the API to record interventions and scheduled follow-ups:

`GET /alerts`, `PATCH /alerts/{id}`, `POST /interventions`, `POST /follow-ups`, `PATCH /follow-ups/{id}/complete`, `GET /notifications`, and administrator-only `GET /audit-logs`.

Alert transitions are validated server-side, case access is role-checked, and important workflow events are append-only audit records. Operational response windows and scoring thresholds are centrally configurable in `governance_config`; they are workflow settings, not clinical claims.

## Phase 4 continuous wellbeing

Victims now have a **My wellbeing** workspace with exactly ten plain-language questions and a database-enforced one-per-calendar-day limit. `POST /api/checkins`, `GET /api/checkins/today`, `GET /api/checkins/history`, and `GET /api/checkins/{id}` reuse the existing deterministic scoring and alert pipeline. The dashboard shows the latest result and recorded history without presenting it as a diagnosis.

`POST /api/checkins/voice` is a consent-gated, provider-neutral upload/transcription hook; audio is not retained by the demo API. Preferences (`/api/preferences`), a minimum-context support assistant (`/api/support/chat`), curated resource links, counsellor intelligence (`/api/counsellor/intelligence`), and administrator monitoring (`/api/admin/monitoring`) are also available. Voice and privacy consent are explicit, and relevant actions are audit logged. Run `server/app/migration.sql` for production databases (startup performs the same additive migration).
